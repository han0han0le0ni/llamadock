# LlamaDock v2.0 · 个人自用版

> **前提（本设计的唯一前提，任何设计决策不得违背）**
> - 个人游玩，**不商用**
> - 个人局域网，**只有我自己的几台设备**
> - **不公布、不分发**，只有一台机器上跑
> - 不做多用户、不做权限、不做对外运营
>
> 一句话原则：**任何为"未知用户 / 多机器 / 分发"服务的复杂度，一律砍掉。**

---

## 1. 这个东西是什么

一个**给自己玩的本地大模型控制台**：

- 双击打开窗口，按钮启动/停止，托盘常驻
- **约 80 个 AI 参数可视化调节**，加载级参数真正变成 `llama-server` 的启动开关
- **硬件自检 + 算术推荐参数**（不用自己猜 `n_gpu_layers` 该填多少）
- 开一个 `:8080` 端口，手机/笔记本/平板在同一 WiFi 下直接连
- 单文件 exe，`go build` 出来就能跑
- **完全独立**：运行期只依赖一份 `llama-server.exe`，不依赖任何外部软件

**职责边界**（一条链路全在程序内）：

| | 谁负责 | 说明 |
| --- | --- | --- |
| 模型文件管理 | ✅ LlamaDock | 扫描用户配置的 gguf 根目录，只读头部拿结构参数 |
| 推理执行 | ✅ LlamaDock | 自己拉起 / 回收 `llama-server` 子进程，只绑回环 |
| GPU 卸载层数 / 上下文 | ✅ LlamaDock | 参数面板 → 启动开关，不再有任何"调不到"的参数 |
| **参数精细化** | ✅ **约 80 项** | 加载级进启动命令，采样级进请求体，两条路不重叠 |
| **参数推荐** | ✅ **硬件自检 + 算术推导** | 每条都给出算式依据 |
| 局域网 API | ✅ OpenAI 兼容 + 多格式 | 对外只暴露这一个口 |
| 请求日志 | ✅ 最近 200 条可查 | 内存环形缓冲 |

## 4. 硬件自检 + 算术推荐（第二个核心价值）

### 4.1 自检（跑一次，缓存）

| 采集 | 方式 |
| --- | --- |
| GPU 型号 / **专用显存** / 当前占用 | NVIDIA → NVML（`nvml.dll`） |
| CPU 核数 | WMI |
| 内存 | `GlobalMemoryStatusEx` |
| 磁盘剩余 | `GetDiskFreeSpaceEx` |

> **只做一条路径**：因为只有我这台机器，**不需要 AMD/Intel 分支，不需要绕 WMI 32 位溢出问题**。检测一次，结果写进配置，之后直接从配置读。

### 4.2 推荐（纯算术，无 AI）

```
① 可用显存 = 专用显存 − 512MB − 当前占用

② cache_type_k/v   可用 ≥ 模型×2.0 → f16
                   可用 ≥ 模型×1.5 → q8_0
                   否则            → q4_0

③ n_ctx   kv_per_token = 2 × n_layer × (n_embd/n_head × n_head_kv) × bytes(cache)
          ctx_max     = (可用 − 模型×1.02) / kv_per_token
          n_ctx       = min(模型原生上限, ctx_max)，向下取 2 的幂
          ★ 显存紧张时降 cache_type，而不是砍 n_ctx

④ n_gpu_layers
          per_layer   = 模型大小 / n_layer
          layers_max  = (可用 − KV(n_ctx)) / per_layer
          n_gpu_layers = min(n_layer, layers_max × 0.95)     // 5% 安全收敛

⑤ n_batch = 512    n_threads = min(物理核, 16)

⑥ flash_attn = true（CUDA/Vulkan 且量化支持）
```

**每条推荐都附算式**，界面上默认可折叠，需要时展开核对：

```
n_gpu_layers  31 / 32
  模型 4.7GB ÷ 32 层 = 147MB/层
  可用显存 4.6GB − KV 0.8GB = 3.8GB
  ⌊3.8GB ÷ 147MB⌋ = 26 层 → 应用 5% 收敛 → 31 层
```

**应用方式**：静默自动填入，顶部一行小字「已根据你的硬件优化 · 查看依据 ▾」。不弹窗。

## 5. 引擎接入（自管 llama.cpp，不依赖外部软件）

```
启动 → 探测 llama-server.exe
  ├── 顺序：用户指定 exe → 用户指定搜索目录 → 程序目录\runtime\llama.cpp\** → 系统 PATH
  ├── 择优：变体优先级 cuda12 > cuda > vulkan > cpu（无 N 卡自动落 CPU）
  └── 都没有 → 状态页明确提示「把 llama.cpp 解压到 runtime\llama.cpp\」，不静默失败

加载 → 拼 llama-server 启动命令
  ├── 「参数」页的加载级参数 → 启动开关（--n-gpu-layers / --ctx-size / --cache-type-k/v / --flash-attn …）
  ├── 端口从端口池挑一个空闲的，只绑 127.0.0.1
  └── stdout/stderr 落盘 + 保留最近 12 行，界面可直接看（OOM、模板不兼容都在这）

运行 → 网关把 /v1/chat/completions 转发到该子进程（含 SSE 流式）
  ├── 请求未加载模型 → 按配置自动拉起；自动加载关闭 → 503 + 明确原因
  └── 空闲超过 idle_unload_minutes → 停掉子进程，把显存还给系统
```

| 能力 | 说明 |
| --- | --- |
| 模型列表 | 扫描用户配置的 gguf 根目录，只读头部拿结构参数（层数/维度/KV head/原生 ctx/量化） |
| 请求转发 | `/v1/chat/completions` → 合并参数 → 转发 → 回传（含 SSE 流式） |
| 可透传参数 | 运行时采样/长度/控制级参数全部显式下发 |
| **加载级参数** | 变成 `llama-server` 的**启动开关**——这正是本程序存在的理由，没有任何"调不到"的参数 |
| 模型加载/卸载 | 加载 = 拉起子进程（同一时刻一个模型）；卸载 = 停子进程，显存立即释放 |

`internal/engine.Adapter` 保留为接口（当前只有一个实现）。要接 Ollama / vLLM 时新增一个实现即可，
上层（core / 网关 / API / 前端）零改动。

## 6. 网关（单端口，无鉴权）

```
监听 0.0.0.0:8080
├── POST /v1/chat/completions     → 转发（支持 stream）
├── POST /v1/completions          → 转发
├── GET  /v1/models               → 模型列表
├── GET  /healthz                 → 探针
└── GET  /api/status              → 状态（给浏览器直接看，方便调试）

多格式（原始需求「支持多种格式」）：
├── Content-Type: application/json        → 单次响应
├── stream=true                           → SSE（data: {...}\n\n ... [DONE]）
├── Accept: application/x-ndjson          → 逐行 JSON
└── ?format=text                          → 纯文本流（浏览器直接看）
```

- **无 API Key**（不公布，没人知道它存在）
- **无来源过滤**（局域网自用，路由器不开端口映射即可）
- 只需保证：`allow_lan_only` 之外**不做任何额外防护**——这是有意识的取舍

**手机接入**：界面显示 `http://192.168.1.100:8080/v1` + 二维码，客户端只填 base_url，Key 留空。
